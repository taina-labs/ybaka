Instalação

Colocar o Tainá no ar.

Este guia assume que você não é técnico: nunca abriu um terminal, ou abriu mas nunca instalou nada. Do começo ao fim, sem ajuda de ninguém, em menos de 30 minutos.

Cada termo técnico deste guia está explicado em uma linha no glossário. Travou numa palavra? Volte lá.

Um Raspberry Pi 5 ou um mini PC, ligado 24 horas por dia. No Raspberry Pi, o binário da CLI é o aarch64; num mini PC, o x86_64.

Um servidor na nuvem, com IP público. Na VPS, o binário da CLI é o x86_64. Aqui faz sentido já subir com o domínio da comunidade.

Se você só quer experimentar numa caixa local, pare depois de criar a comunidade. Domínio, acesso remoto e disco de backup são para quando a comunidade for usar de verdade.

Instale o Docker

O Tainá roda dentro do Docker. Isso mantém o resto da máquina limpo e faz a atualização ser um comando só. No Linux e no Raspberry Pi OS, cole o bloco abaixo e aperte Enter:

Terminal 
curl -fsSL https://get.docker.com | sh

O script pergunta se quer adicionar o Docker ao grupo de administradores. Responda que sim e abra o terminal de novo para valer nesta sessão. Confira com docker --version: uma linha com o número de versão, e está pronto.

Instale a CLI do Tainá

A CLI é o programa que opera a caixa: instala, atualiza, mostra os logs e faz o backup. Baixe o binário da página de releases do Oka para a arquitetura da sua caixa e instale:

Máquina própria (aarch64) 
sudo install -m755 taina-aarch64-linux /usr/local/bin/taina
                    taina version
VPS (x86_64) 
sudo install -m755 taina-x86_64-linux /usr/local/bin/taina
                    taina version

O último comando deve imprimir algo como taina 0.1.0. Se imprimir, está pronto.

Instale o Tainá

A forma normal é baixar a imagem pronta. O setup confere o Docker, sorteia o segredo das sessões, sobe o container com o banco da comunidade e espera o aplicativo responder que está saudável:

Terminal 
taina setup

Ele escreve um arquivo taina.conf com o segredo. Guarde esse arquivo com cuidado: quem tem ele tem acesso à caixa. Rodar o comando de novo não sobrescreve nada. No final, ele imprime o endereço para o próximo passo.

Se o setup reclamar que a imagem não está disponível, dá para montá-la na própria caixa a partir do código com o build-image.sh do Oka. Aí rode TAINA_IMAGE=taina:local taina setup. O guia completo tem o passo a passo.

Crie a comunidade

Abra no navegador o endereço que o setup imprimiu, terminando em /setup. Vão aparecer três telas:

  • Nome da comunidade. Cada instância é uma comunidade só, e o nome é definitivo para sempre.
  • Quem cuida da máquina. Um nome de usuário, um nome de exibição e uma senha. Essa pessoa é a zeladora, não administradora.
  • Armazenamento. O Tainá mostra onde os arquivos vão ficar e quanto espaço livre existe.

Depois do último passo você entra logado. A comunidade foi criada e você é a primeira pessoa dela.

Convide a primeira pessoa

No menu, abra Membros e depois Convidar. O Tainá mostra um link de convite e um QR code. A pessoa abre e cria a conta dela. Não existe e-mail no Tainá, e isso é uma decisão: menos uma senha guardada em servidor de terceiro.

Acesse de fora da rede

Dentro da rede local o endereço já funciona. De fora, o caminho que a gente recomenda é o Tailscale: ele dá um endereço seguro à caixa, com HTTPS de verdade, sem abrir porta nenhuma. Instale o Tailscale na caixa e no aparelho de quem vai acessar, entre na mesma conta nos dois e rode:

Terminal 
tailscale serve --bg 4000

Depois, escreva esse endereço no TAINA_DOMAIN do taina.conf e rode taina update, para que os convites saiam com ele. O guia de acesso remoto tem as outras opções, como o seu domínio com Let's Encrypt.

Ligue o backup

O backup vem desligado. Uma comunidade de verdade precisa dele ligado, e precisa de uma cópia em outro lugar, não só no mesmo disco. Monte um disco externo, dê a pasta ao usuário do container e aponte o backup para ela:

Terminal 
sudo chown 65534:65534 /mnt/backup
                    taina backup --out /mnt/backup

No taina.conf, descomente TAINA_BACKUP_DIR=/mnt/backup e mude TAINA_BACKUP_ENABLED=true. Rode taina update e, a partir daí, um backup é feito todo dia. E ensaie a restauração: um backup que nunca foi testado não é backup.

Para atualizar depois, é um comando só: taina update. Ele baixa a versão nova, recria o container e confere a saúde. As migrações de banco rodam sozinhas no boot.
